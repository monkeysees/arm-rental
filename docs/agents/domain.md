# Domain docs

## Layout

Single-context: root CONTEXT.md and docs/adr/.

## Before exploration

Read README.md and docs/architecture.md, then CONTEXT.md and relevant ADRs
when present. Proceed silently when CONTEXT.md or ADRs are absent;
domain-modeling creates them as terms and decisions are resolved.

## Vocabulary and decisions

Use glossary terms consistently in tickets, tests, and design discussions.
Flag conflicts with existing ADRs explicitly.
Keep docs/architecture.md current as required by the repository instructions.
